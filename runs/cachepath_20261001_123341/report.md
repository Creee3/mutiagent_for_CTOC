# 同一缓存的接口对照

这一个固定案例里的措辞分歧，不是KVComm接口独有。绕过KVComm、使用Qwen原生缓存复用，也复现相同分歧。

沿用上一轮首题，重新生成同一A历史，接收方B分别走三条路径。条件仍为学校服务器Qwen7B、BF16/SDPA、greedy、重复惩罚1、256预算，完整缓存。

| B的计算方式 | 末句 | 输出长度（含EOS） |
| --- | --- | --- |
| 把A历史和B提示整段重算 | which means German | 50 |
| Qwen原生接口复用A缓存 | which corresponds to German nationality | 52 |
| KVComm接口复用同一A缓存 | which corresponds to German nationality | 52 |

原生缓存与KVComm的52个生成token完全一致，但logits仍有最大0.0625差异，不能称逐位等价。整段重算与缓存复用在第47个token分岔；候选词分数差仅0.125。所有路径正常EOS结束，无触顶。

4次生成+1次补尾全部成功，197个生成forward的位置核对正确，发送方输出复现上一轮。两种缓存接收只前向191个新增提示token，199个已有历史token由同一份缓存提供；源缓存保持不变。实际A缓存张量11,411,456字节，精确文本token内容796字节，另有元数据；未测网络。

这支持差异与“整段重算/复用缓存”两种计算路径有关，尚未隔离具体精度或算子来源。当前无需凭这处分歧修改KVComm协议或增加生成预算。

下一步应在单独固定条件下检查真正A→B→C自由接力。用原生缓存接收作为实现控制，同时把全文重算保留为质量对照，输出措辞差异如实记录。上一轮的严格门禁失败记录继续保留；本检查不是三节点自由链已通过的证明。
